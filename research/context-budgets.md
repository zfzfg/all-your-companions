# Context budgets

The resolved CLI session budget is independent of public API capabilities, billing tokens, subscription quotas and Crew spending budgets. `src/context-budget.ts` validates and resolves observations; `src/context-catalog.ts` reads sanitized native catalogs. Live verified session limits take precedence over native catalogs, followed by marked estimates. Unknown model IDs have no invented capacity.

Native Grok catalogs use `models[id].info.context_window`. Codex catalogs apply `effective_context_window_percent` once; session measurements are already effective. For GPT-6.1 Sol this means 272,000 × 95% = 258,400 in the inspected CLI catalog. Its [public API maximum](https://developers.openai.com/api/docs/models/gpt-6.1-sol) is 1,050,000 with 128,000 output tokens. The [Grok 4.7 API](https://docs.x.ai/developers/models/grok-4.7) maximum is 500,000; the inspected Build catalog grants 256,000. API references are displayed separately and never enlarge a verified CLI budget.

Grok and Codex catalogs refresh at connection, explicit refresh and send, and watch directory changes with debounce. Cache identity includes provider, credential identity hash, access metadata and executable/version scope; credentials and headers are not persisted or logged. Catalogs older than 24 hours remain visible as stale. New catalog model IDs are added automatically. Claude unannotated adapter limits remain estimated; Antigravity accepts native model metadata and keeps exact access-specific fallbacks, without a generic 1M default. Muse uses validated native context limits.

Observations carry model, access, session, generation, source, timestamps and independent limit/usage quality. Model changes clear old usage; tagged late updates are rejected. Historic persisted observations are stale until refreshed. Forks start without the parent's budget state. Zero usage and occupancy beyond the capacity are valid measurements.

Every ACP `prompt` call passes through the same preflight and sends the checked snapshot unchanged. `contextTokenCounter` is an optional integration hook for a verified complete serialized request. A fully verified excess blocks before RPC; incomplete text estimates warn and permit sending. Native adapters currently own hidden history, system prompts, tool results and multimodal accounting, so the default host estimate cannot provide complete hard enforcement. Unknown limits produce one warning per model generation. Native compact/clear/info commands bypass the guard to allow recovery. Output reserves are used only when known and are not subtracted from input-only or already reserved effective budgets.

Blocked drafts and attachments remain recoverable. Manual compact requires an affirmative capability, and a failed compact restores the draft without resending the agent turn. Automatic provider compaction and explicit environment settings remain provider-owned. The 80% fallback is an advisory threshold only.

Tests: `context-budget.test.ts`, `context-budget-acp.test.ts`, `context-catalog.test.ts`, provider normalization tests, persistence/dispatch tests and webview DOM tests. CI uses fake providers and temporary catalogs; it never sends paid overflow prompts. CLI configuration effects and untagged delayed events require native adapter evidence before stronger guarantees can be made.
