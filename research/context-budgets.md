# Context budgets

The resolved CLI session budget is independent of public API capabilities, billing tokens, subscription quotas and Crew spending budgets. `src/context-budget.ts` validates and resolves observations; `src/context-catalog.ts` reads sanitized native catalogs. Live verified session limits take precedence over native catalogs, followed by marked estimates. Unknown model IDs have no invented capacity.

Native Grok catalogs use `models[id].info.context_windows` in native order, with `context_window` as the legacy single-size fallback. ACP `_meta.contextWindows` also populates `ModelInfo.contextWindowSizes`. The first offered size is the native default; confirmed active selection remains separate. Native Windows Grok 1.0.46 was verified with 256,000 and 500,000 choices. Neither spelling heuristics nor public API numbers resolve CLI capacity. Session-confirmed active windows take precedence over catalogs regardless of their numeric value.

Codex catalogs apply `effective_context_window_percent` once; the shipped ACP adapter 1.11.0 reports its session capacity through `usage_update.size`. Its `TokenCount.toTokenCount` subtracts cached input before exporting `cachedReadTokens`, so ACP input/cache partitions are disjoint. Claude ACP 0.76.0 exports accumulated turn usage: a turn sum never becomes native current-context occupancy. Last-request/per-call figures support clearly marked text estimates only. A bare billing total does not estimate occupancy; Claude's synthetic post-compact zero without `post_tokens` is not an empty-context measurement.

Muse SDK 1.3.0 defines `session/contextUsage` as counted-once occupancy and an optional effective window. The existing projection preserves that source; resume returns the snapshot alongside the model response so initialization cannot erase it. `usage/read` and `usage/changed` remain subscription data. Antigravity stream-json usage has no verified current-context semantics; the adapter does not synthesize session-info from billing totals. Native model metadata can supply capacity, but static fallback model names supply no token limit.

Catalogs refresh at connection and send and watch directory changes with debounce. Access changes clear resolved aliases, old context choices and occupancy. Exact model IDs and explicitly observed native resolved IDs are the only matches. Catalogs older than 24 hours remain stale. Provider runtime, pinned adapter version and negotiated protocol version are recorded where known; Muse also preserves the MSP server and schema versions. Raw backend payloads remain transient and never enter ContextObservation or persisted metadata. Fixtures in `test/fixtures/native-context-contracts.json` are pinned schema/source examples, not live captures.

Observations separate catalog maximum, configured/active window, effective input budget and token/percent compact thresholds. Limit and occupancy have independent source, quality, observation time and stale state. Process/session/model/compaction revisions reject obsolete observations; old process callbacks cannot modify a new client lifecycle. Compaction invalidates occupancy while retaining capacity; a native replacement can decrease or be zero. Historical observations remain stale estimates. Public API tables without versioned source evidence are not shipped.

The popup keeps the confirmed active Grok selection usable even without an effective input budget. A ratio uses matching, fresh native occupancy and native capacity (including Grok's confirmed active selection); estimates and historical values appear as text without a percentage ring. Unknown is not zero. Occupancy beyond capacity remains visible as an inconsistency, never a claim that Antigravity already compacted. Manual compact follows provider capabilities even when occupancy is unknown.

Every ACP `prompt` call passes through the same preflight and sends the checked snapshot unchanged. `contextTokenCounter` is an optional integration hook for a verified complete serialized request. A fully verified excess blocks before RPC; incomplete text estimates warn and permit sending. Native adapters currently own hidden history, system prompts, tool results and multimodal accounting, so the default host estimate cannot provide complete hard enforcement. Unknown limits produce one warning per model generation. Native compact/clear/info/context-window commands bypass the guard to allow recovery. Output reserves are used only when known and are not subtracted from input-only or already reserved effective budgets.

Blocked drafts and attachments remain recoverable. Manual compact requires an affirmative capability, and a failed compact restores the draft without resending the agent turn. Automatic provider compaction and explicit environment settings remain provider-owned. The 80% fallback is an advisory threshold only.

Tests: `context-budget.test.ts`, `context-budget-acp.test.ts`, `context-catalog.test.ts`, provider normalization tests, persistence/dispatch tests and webview DOM tests. CI uses fake providers and temporary catalogs; it never sends paid overflow prompts. CLI configuration effects and untagged delayed events require native adapter evidence before stronger guarantees can be made.


## Native Grok context selection

The model picker proceeds from model confirmation to context choices and then reasoning effort; the context popup exposes the same choices. New sessions retain the CLI default. `/context-window`, `/context-window 500k`, and `/context-window 500000` are host-routed controls and preserve drafts and attachments. Controls are unavailable during a turn, startup, or an outstanding context change. The host validates session, model, generation and offered size; the client also refuses concurrent model/config RPCs.

CLI 1.0.46 advertises `_meta.contextWindows` but **does not advertise or dispatch `/context-window` over ACP**. Its TUI command is not an ACP slash command. The verified ACP path is `session/set_model` with `_meta.contextWindow` and the current reasoning effort, followed by `_x.ai/session/info` confirmation. The extension enables this path only for a live-verified CLI >=1.0.46; an explicitly advertised native slash command uses the bare native prompt path instead. Unsupported typed commands never become ordinary model prompts.

`ContextWindowSelection` carries offered/default/confirmed sizes and the changing flag independently from `ContextObservation`. Accepted changes advance the context generation and invalidate the old limit. Confirmation publishes the real active native window separately from an optional effective input budget. Legacy limit quality remains estimated for server enforcement; it does not invalidate the verified native selection or its UI controls. Errors restore the last confirmed view as stale. Catalog refreshes do not overwrite it. New and resumed sessions query native state; compatible model switches inherit the CLI's choice. Shrinking and auto-compaction remain native behavior. Tagged old updates are rejected; untagged delayed native events cannot be assigned stronger identity than the CLI supplies.

FireInWinter identified the native feature in [upstream issue #202](https://github.com/phuryn/grok-build-vscode/issues/202#issuecomment-5936310443). The control-plane-only `research/context-window-probe.cjs` verifies default, enlargement, catalog refresh, model carry-over, shrinking and resume on native Windows CLI 1.0.46, without model prompts or overflow requests. Binary-free coverage lives in `context-selection.test.ts`, `context-selection.dom.test.ts` and the inbound router tests; screenshot fixtures cover Dark, Light and High Contrast.
